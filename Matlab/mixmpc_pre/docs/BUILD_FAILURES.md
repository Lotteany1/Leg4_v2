# 融合 MPC 构建报错与维护约束

本文针对 `build_mixmpc_pre` / `build_mixmpc_pre_fast`，不是旧 `balance_mpc` / `leglen_mpc`。后续 AI 必须先确认用户的错误堆栈指向哪一条链。

## S8 G19 的真实失败点（2026-11-17）

用户错误堆栈：`build_mixmpc_pre → tinympc14_deploy → tinympc14_build_and_verify → s08_tinympc14_runtime_check → assert(g19)`。

虽然 G19 标题写“H 跟踪”，但非对称腿长场景（场景 5）实际比较的是腿角、机体俯仰、横滚中的最大姿态误差。该场景腿长 0.25 / 0.29 m，目标横滚非零。修改前最大误差 LQR 约 0.0001 rad、MPC 约 0.0129 rad，因而触发原有 20% 门限。其余 G18、G20～G27 均通过。

根因是**运行时预测与闭环验证对象的扰动定义不一致**：

- 运行时含等效倾覆差模力 `tip = ROLL_TIP_GAIN*M_SUP*g*(height+H_OFF)*roll/(2*R_TRK)`，按 `[+tip;-tip]` 经 Bd 的两条轴力列进入 `fed`。
- 原 S8 plant 只有 `Ad*x + Bd*u + fd`，没有该外扰；LQR 对照的 `fed` 也为零。
- 非零目标横滚下，MPC 为抵消“预测有、plant 没有”的力矩产生持续差模力，形成假稳态误差。不能据此归罪于 Q/R 或 H7 计算超时。

单变量诊断：

| 版本 | 场景 5 的 LQR / MPC 最大姿态误差 | G19 |
| --- | --- | --- |
| 原验证链 | 9.57e-5 / 0.012905 rad | FAIL |
| 诊断中暂关预测倾覆项 | 9.57e-5 / 2.09e-8 rad | PASS |
| 仅给两条 plant 加同一倾覆项 | 0.042425 / 2.09e-8 rad | PASS |
| plant 与 LQR 预测均补齐同一合同（最终） | 9.57e-5 / 2.09e-8 rad | PASS |

“关闭倾覆项”仅用于定位，未作为修复提交。最终保留用户当前所有配置，特别是两路轮矩 R=1.3；没有调低 G19 门限，也没有跳过失败场景。

## 正确的代码合同

- `functions/tinympc14_roll_force.m` 由观测绝对高度和横滚角求经验倾覆矩，再用预测工作点的横滚角及左右矢状腿角，换算为零升降广义力、指定横滚矩的两条等效轴力。固定模型采用冻结工作点，非线性积分采用中间状态的姿态。
- `functions/tinympc14_runtime_step.m` 从输入快照恢复绝对高度，计算同一外扰，并经当前 Bd 投影进预测。实车在固件侧分别提供高度反馈和倾覆估计所需的高度。
- `functions/tinympc14_plant_step.m`：S8 的冻结 ZOH plant，将同一外扰与已下发命令一起作用到模型；对 LQR 和 MPC 完全相同。
- `verify/s08_tinympc14_runtime_check.m`：LQR 预测也计入该已知外扰，保留原 G18～G27 和 G19 的 20% 门限。
- `verify/s10_tinympc14_nonlinear_check.m`：RK4 每个中间状态重算该外扰，不能只在采样起点算一次后当作常量用于整段非线性积分。
- `verify/tinympc14_roll_contract_check.m`：正、负、零横滚下检查力矩/符号、等量反向输入能否抵消 plant 外扰、运行时 fed 是否一致。完整与 fast 默认验证都调用。

S8 的冻结线性模型不一定恰好在非线性平衡点展开，因此合同测试比较“加入扰动并抵消之后”与该冻结模型原始响应；不能要求任意展开点都严格静止，也不能为制造静止修改仿射残差。

这是已实现等效扰动模型的一致性修复。`ROLL_TIP_GAIN=0.4` 的实物精度仍需辨识；该测试不等同真实机器人稳定性或 H7 实测。

## 生成段连续写入失败

完整构建另两次复现 `tinympc14_section → Cannot write tinympc14_data.c: Permission denied`，均在 LPV 写入之后追加 ZOH 时发生。故障时 MATLAB 没有未关闭的 fopen 文件，稍后新进程可正常打开，说明不是持久只读属性；具体外部占用者未确认。

段写入现先在同目录完成 UTF-8 临时文件，再替换目标；Windows 替换遇占用最多等待约 1 秒，仍失败则保留明确错误，不能吞错后继续生成清单。不能再使用 `fwrite(txt,'char')` 写 Unicode 字符，这会丢失中文。C 源文件的新段追加到末尾；只有头文件声明段插在最终 `#endif` 前，避免 ZOH 被嵌套进 LPV 内部打包头文件的保护宏中。

修改生成/拼段逻辑后运行 `tinympc14_section_check`：连续替换约 2 MB 的 C 段、追加独立段、UTF-8 中文往返、头文件保护宏位置和临时文件回收均必须通过。临时文件只用于构建，不增加部署 solver/data 文件数。

## 构建与缓存

相对输出路径先由 `Tool/shared/mpc_output_path` 与 MATLAB 当前 `pwd` 拼接，再规范化。禁止直接将相对路径交给 Java `getCanonicalPath()`：JVM 的启动目录可能与 MATLAB `cd` 后的目录不同。入口应在任何子步骤切换目录前固定目标。

新增/修改生成依赖必须加入 `tinympc14_manifest_sources`。修改源码、模型、物理量、周期或 rho 后先完整构建；不要手工更新缓存哈希来绕过 `CacheStale`。仅改 Q/R-BLOCK 内权重，才使用 fast。完整生成新表后清除 MATLAB 持久缓存，避免同一会话继续读取上轮数据。含 clear 的验证脚本必须经独立 run_stage 工作区运行，不能内联进持有参数和 onCleanup 的构建入口。

验证完成后还要在用户实际目录构建，不能只更新 diagnostics 的副本。用户已明确授权日常完整和 fast 默认同步拆分包到 `Wheel_Leg_Code/Code/Model`；`build/polynomial_package` 是构建副本。显式诊断输出仍只写指定目录，不自动烧录。

## 必跑验证

从 `Matlab/mixmpc_pre`：

```matlab
mixmpc_paths;
tinympc14_section_check;
tinympc14_roll_contract_check;
run(which('s08_tinympc14_runtime_check'));
run(which('s10_tinympc14_nonlinear_check'));

```

若源码变更使已有表过期，应先完整构建；不能以旧表运行局部验证后宣称完整验收。完整入口应经过生成表/来源哈希、QP、离网格调度、S8/S10 和主机 C 对拍。fast 不代替完整闭环验收。

当前证据目录：`Wheel_Leg_Code/diagnostics/matlab_build_repair_20261117/fused`。`probes.log` 和各 `.mat` 保存单变量定位；`runtime_final.log` 保存 S8/S10；`build_verified.log` 保存最终完整与 fast 入口；`build_final*.log` 保留文件占用失败证据；`before/` 保存本次修改前源码。配置文件哈希可核对本次未修改用户参数。

## 轮端约束激活时的数值尺度与工作区（2026-11-18）

将轮矩箱修正到驱动器可接纳范围后，冻结在线配置的第 9 号回放在 100 次预算内仍有约 0.166 N·m 的首节点轮矩原始残差；同一问题的独立 QP 有可行最优解，诊断长预算需要 3424 次才收敛。原因定位到约束激活时的 ADMM 收敛尺度，不是约束不可行，也不能据此判断 H7 算力不足。

该版输入罚参数按轮通道 `max(rho,Rwheel)`、其余通道 `rho` 使用，同步修改增广 Riccati、反向线性项和对偶残差。Q/R 目标、状态罚参数、终端代价、物理约束、容差和 100 次预算保持原定义。在线后备增益用原标量 rho 的末级因子单独生成，MATLAB `tinympc14_lpv_eval` 同步使用这个后备增益。

对称 Riccati P 只保存下三角且保持 double 与原累加顺序；投影在箱解已经满足速率约束时直接返回，再为其余情况构造原有精确活动集。六个输入罚参数仅在模型更新时重算。不能改成只裁第一步、忽略速率或状态约束，也不能把不收敛回退计作加速。

冻结在线配置证据位于 `Wheel_Leg_Code/diagnostics/tinympc14_goal_20261117`：2000 回放全部收敛，原失败帧为 26 次；固定额外 4000 常规和 1000 压力帧全部收敛，最大分别 31/69 次；64 个独立 QP 的整段序列最大误差 `1.813e-4`，原门槛 `2e-4` 未变。原型、单末级计算、缓存罚参数与重新生成包的结果逐位相同。这些统计属于冻结配置，不能当作任意用户参数或物理闭环验收结果。

最终实际源码整合的备份、配置漂移记录、完整/fast 包和隔离 AC5 构建放在 `final_apply_20261118`。H723 时序与动态栈水位仍需实测；物理控制效果不能仅凭这些数值回归宣称达到旧双 MPC 水平。

六文件日常布局的严格 Clang 接入检查曾因 `Tinympc14_Admm_Reference_Model` 未使用而失败。该函数只服务在线模型接口，声明和定义均须置于 `TINYMPC14_ONLINE_IFACE_VER` 条件内；修复模板后重新生成并复验，不关闭 `-Werror`。最终整合结果以 `final_apply_20261118/FINAL.md` 为准，下面的早期构建统计保留为历史证据。

## 髋部速度口径与执行约束（2026-11-18）

`body.vel` 包含轮心速度和摆腿/伸缩速度；已修复双 MPC 也使用两髋平均位置/速度。融合 `tinympc14_bal_block` 的变换首行原为 `[R_w/2 R_w/2 0 0 0]`，仍表示两轮心平均速度。现补入 `lL/2,lR/2`，与固定腿长、小角度下 `s_hip=s_wheel+(lL*psiL+lR*psiR)/2` 一致。单变量相似变换检查 30 组腿长最大误差 `4.45e-15`。这不是完整变腿长多体模型，不能将 `kin_ldot` 的推导登记误称为已实现所有伸缩耦合。

此改动首次完整构建在动量检查报约 `576` 的残差：检查中的动量系数仍以轮心速度写成。将同一物理动量代入 `v_wheel=v_hip-(lL*dpsiL+lR*dpsiR)/2` 后，残差约 `1.85e-13`；原 `1e-6` 门限不变，检查未删除。改动模型状态坐标时，物理不变量的系数也必须按坐标变换，不能只改期望数值。

融合轮矩约束原为 `±6 N·m`，发送层实际限幅为 `16384/3326.29 ≈ 4.925608 N·m`。预测约束现与发送能力一致，Q/R 不因此改动。`balance.c` 另恢复已计算并记录的 `Turn_DistF` 到预测扰动，不在电机出力重复叠加。生成后的 solver/data 需整包复验；源码修复不等于已替换板端映像。

证据和失败日志保存在 `Wheel_Leg_Code/diagnostics/tinympc14_goal_20261117`。并发运行多个 MATLAB/Coder 时出现过明确的“内部错误: 内存不足”，以及新 MATLAB 进程 `abort()`；后者具体原因未确认。保留失败并在新进程串行复跑，不以此为由跳过 fast、降低门限或伪造缓存来源。独立 CAD 闭环仍存在参数族差异和预测域越界，不能据此宣称实车性能或实时性达标。

## 双腿轴力达到变化率约束时的收敛（2026-11-19）

最终工作区的横滚角、角速度权重为 1000、100，双腿轴力的 R 均为 0.01。保持这套数据和 100 次迭代预算，在隔离的生产 C 副本中仅切换轴力通道的 ADMM 罚参数。取原值 0.001 时，1000 个随机样本中仅 4 个按时收敛。两路轴力和两路轮矩都采用 `max(rho,R_i)` 后，1000 个样本全部收敛，迭代次数中位数 31、最多 38。髋通道仍取 `rho`。原始和对偶残差最大值分别为 `9.994e-5` 和 `9.997e-8`。

生成入口 `build_mixmpc_pre` 中的 `tinympc14_qp_check` 对照 MATLAB `quadprog` 检查可行域和最优输入。专门触发轴力变化率限制的工况在 27 次内收敛。独立的 25 个 OSQP 样本另行检查最终 C 包，整个七步预测序列的最大轴力误差为 `1.751e-5 N`。这些测试检查数值求解，实车是否频繁限速或切换回退需要对照现场记录。
