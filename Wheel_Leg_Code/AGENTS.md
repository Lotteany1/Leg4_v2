# Wheel_Leg 代码规范（AI 硬约束）

- 平台 STM32H723 + AC5 + FreeRTOS(CMSIS-RTOS2) + HAL；本文件是硬约束，与你的默认习惯冲突时以本文件和既有代码为准。
格式唯一权威是根目录 `.clang-format`，配置必须与本文件的 Allman 大括号和空格规则一致。动笔前先读当前同目录文件及旧工程对应文件。

## 1. 注释

- 全工程迁移旧工程中仍与当前实现一致的职责、算法步骤、时序、单位和边界注释，优先保留原有说法，不能只留下函数名的简短改写。已更改的周期、接口、模型参数和任务分工必须按当前实现修正，禁止照搬失效说明。
- 函数上方说明职责、关键调用顺序和副作用。函数体内允许保留或补充必要的算法步骤、状态转移、快照交接和坐标变换注释；使用短段落，放在相应代码块上方，不逐行复述代码。
- 每个 `switch` 的每一个 `case` 和 `default` 都必须有注释，说明该分支的条件、动作或出力含义。合并分支也逐项注明，避免只在枚举定义处说明。
- 枚举上方保留用途说明，成员逐项标注；宏、结构体字段和 API 声明注明含义与单位，参数方向、坐标系和每拍调用限制要写清楚。同组宏、赋值和连续声明的行尾注释对齐。
- 必要时允许沿用旧工程的括号、公式和多行解释，但应准确简洁；不复制旧 `//?` 调试占位、无效出处行号、注释掉的死代码和失效 TODO，不加入变更日志式说明。
- 不新增装饰横幅或编号分区，使用函数顺序和空行组织。第三方库与 MATLAB 生成文件保留原有许可证、生成来源、公式和参数说明，不能用旧模型说明覆盖新模型含义。
- 范围为全工程自有代码，不限于 FSM。CubeMX 文件仍只在 USER CODE 区内处理，第三方目录不做批量注释或排版修改。

## 2. 命名

- 函数与文件内 `static` 辅助函数：`模块_动作` PascalCase + 模块前缀（`Can_Bus_Send`、`Dm_Wait_Tx_Ready`）。
- 类型小写下划线 + `_t`（`dm_motor_t`）；宏全大写带模块前缀（`DJI_M2006_SET_MAX`）。
- 实例小写模块前缀 + 位置缩写（`dji_wheel_lft`、`dm_f_lft`）；缩写词表 `lft/rgt/f/b/cmd/cfg/tx/rx`。
- 目录名 PascalCase，文件名全小写下划线；浮点常量带 `f`，无符号字面量带 `u`。

## 3. 文件组织与文件头

- 文件头：`/** @file  xxx.c  @brief 一句话职责  @version  vX.Y  日期 */`（`.h` 同规格写 `xxx.h`，`@file` 后两个空格）；其余目录的旧两行头（`// 模块名头文件` + `// 版本：vX.Y`）待逐文件迁移，不做批量重排。
- `.c` 顺序：文件头 → include（自身 `.h` 优先）→ 宏 → 实例定义 → `static` 配置表 → 前置声明 → `static` 辅助函数 → 公有 API；静态配置表必须用指定初始化器 `.field = value`。
- `.h` 顺序：文件头 → include guard → include → 宏 → 类型/枚举 → `extern` 实例 → API 原型；函数声明不加 `extern`；不写 Doxygen 参数表。

## 4. 代码格式

- 按旧工程使用 Allman 大括号：函数、`if / else`、`switch`、循环和类型定义的 `{` 独占一行，`else` 单独起行；禁止 `if (...) {`、`} else {` 和单行带大括号代码块。
- 旧工程式短早退可写成 `if (条件) return;`；多语句分支使用独占行的大括号，不为压缩行数合并逻辑块。
- 4 空格缩进，无 Tab；`if (`、`switch (`、`for (` 等关键字后一个空格，普通函数调用名后不加空格，二元运算符两侧留空格。
- 变量声明与执行语句、相邻职责代码块之间留一个空行；同一组连续计算或赋值不逐行插空行；函数之间留一个空行，不保留连续空行或含空格的空白行。
- `case` 缩进，连续宏、赋值及行尾注释对齐，不限列宽。根目录 `.clang-format` 对 C 与头文件使用同一套规则；修改格式要求时同步修改配置，不批量重排第三方或 CubeMX 生成区。
## 5. 硬件与 RTOS 硬约定

- CubeMX 是外设配置唯一权威：手写只写进 `USER CODE BEGIN/END` 区；FDCAN 波特率/位时序/报文 RAM 代码只读不写；接管中断的固定套路是 `USER CODE BEGIN <IRQn> 0` 内调用驱动入口并用 `#if 0` 包掉生成的 HAL 调用。
- ISR 只做三件事：取计数、打包快照、置 `volatile` 标志；禁止在 ISR 里跑 CRC、浮点解析、阻塞延时、动态分配。
- ISR 与任务共享字段必须 `volatile`；多字段快照用 `aligned(8)` 的单个 `uint64_t` 读写；跨临界区成对使用 `taskENTER_CRITICAL` / `taskEXIT_CRITICAL`。
- 控制帧"满即丢"（FIFO 满即返回 `HAL_ERROR` 并计数）；使能/清错等关键命令"宁可等"（等到有空位或超时）；两者不要混用。
- 硬件/总线接口返 `HAL_StatusTypeDef` 或 `bool`；纯算法模块 `void` + 入口早退（NaN/非法 dt 直接 return）；禁 `printf` 报错与全局错误码。
- C 库堆仅 512 B：禁 `malloc` / `calloc` / `free`；确需动态内存只能 `pvPortMalloc`（FreeRTOS heap_4）。
- 编译：AC5 + C99 + gnu 扩展 + `-O3` + 双精度 FPU，禁 C11 语法；`Code/` 由 EIDE 编译，新增 `.c` 与子目录必须进 EIDE 源列表与包含路径，否则等于没编译。
- 新任务：`osThreadNew` + `const osThreadAttr_t` 指定初始化器，栈按字节 `N*4`，默认 `osPriorityNormal`，任务体 `for (;;) { …; osDelay(...); }`。

## 6. 改动规矩与既有例外

- 最小 diff：不顺手重构、不动无关注释与格式、只在功能变更时更新版本行与日期、不写变更日志式注释、不留注释掉的死代码。
- git 写操作（commit / push / reset / rebase 等）必须先询问用户并得到当次明确同意才执行；计划或任务描述里写了提交安排也不视为授权。
- Git 提交命名规则仅对新提交生效，不重命名已有历史。标题格式为 `类型: 动作＋具体对象＋必要的行为结果`，直接说明主要改动，中文尽量控制在 15～25 字，清楚优先；允许保留 POS/YAW、LESO、MPC 等明确的技术缩写，例如 `feat: 增加驻车POS/YAW LESO补偿`。
- 提交标题使用明确动作，如增加、修复、拆分、调整、移除；避免用完善、优化、整理、保存基线、调试基座等笼统说法代替具体改动。新增功能用 `feat:`，缺陷修复用 `fix:`，文档用 `docs:`，纯格式用 `style:`，实验产物归档用 `chore:`。
- 标题只写主要改动；次要改动、参数细节、影响范围和验证结果写入提交正文并用条目展开，未验证的效果不得写成结论。
- swarm / AgentSwarm 一律用默认模型，严禁显式指定 `model` 参数。
- 既有例外一律不要模仿：`imu.c`/`dr16.c` 版本行漏了的 `?`、非法宏名 `Leg_Len_Max` / `DR16_Max` / `Hi229`、`dr16.h`/`dr16.c` 的注释死代码。

## 7. 反过度防御

- 校验只在入口做一次 进入函数先把指针 量程 有限性 单位 坐标系一次判完 之后各层直接使用
- 拒绝重复判空与重复判有限 上游判过的量下游不再判 不在同一拍对同一量判第二次 不为清零再清零一遍
- 单次逻辑不乱抽函数 只在一处出现的逻辑写在原地 只有真正多处复用或职责独立才抽
- 不叠错误包装 单层返回 不做多层错误码与套娃失败分支 失败处理只写在真正可恢复处
- 低概率防御先征求同意 不为理论上的空指针 溢出 并发 竞态时序预置机制 需要时先问再加
- 不确定要不要加时先不加 把疑虑写进回复 不要默默堆进代码
- 不算过度防御的 入口 NaN 与非法 dt 早退 硬件接口返回类型 安全层使能确认与 active_flag 锁存 跨临界区 码流与 CAN 帧合法性 这些照旧保留
