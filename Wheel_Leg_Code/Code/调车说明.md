# 新车参数与调试入口

`system_key.h` 管理滑移估计、离地检测、执行分配与动作功能开关。TinyMPC14 是双轮接地的控制器，参数由模型生成链发布。

## 调车顺序

| 阶段 | 修改或观察入口 | 进入下一阶段的条件 |
|---|---|---|
| 硬件通信与使能 | CubeMX 外设配置、电机驱动配置表、`IMU_USE_HI229` | 电机位置与 ID 对应；遥控和 IMU 帧正确；反馈、离线检测、失能与安全锁存正常。 |
| 坐标系与零点 | `polarity_config.h`；轮电机方向与关节反馈 | 手动改变姿态与关节位置时，角度、角速度、轮速方向符合约定；左右镜像与零点对应实物 |
| 物理量与模型 | 下方参数表及完整重建入口 | 几何、质量、质心、惯量、弹簧与力矩换算已按新车核对，生成物与配置验证一致 |
| 基础平衡与腿长 | `tinympc14_data.h`、`BALANCE_USE_SLIP`、`BALANCE_USE_AIR_CHECK` | 在支架辅助下核对反馈和出力方向，再验证基础站立、腿高变化及接地切换 |
| 分配与平衡约束 | `BALANCE_USE_DISTRIBUTOR`、`BALANCE_DISTRIBUTOR_COMPARE` | 核对总支持力、髋力矩、电机能力界、饱和和实际执行记录 |
| 运动与转弯 | `BALANCE_USE_TURN_LIMIT`、`BALANCE_USE_VEL_LIMIT`、`LEGLEN_TURN_ENABLE` | 依次验证低速直行、加减速、停车、原地转向和行进转弯；降高与侧倾放宽方向、限幅和恢复正确 |
| 补偿与观测器 | `BALANCE_USE_ROLL_COMP`、`BALANCE_USE_CORIOLIS_TP`、`BODY_ROLL_USE_KALMAN` | 观察估计与补偿量，验证方向、幅值和饱和，记录序列回退和超龄 |

坐标系沿用右手系：Yaw 逆时针为正、Pitch 低头为正、Roll 右倾为正，腿世界系角前倾为正。关节标定采用 `逻辑值 = raw × 极性 + 零点`；偏置角单位为 rad。

主控制和估计周期为 1 ms，`Tinympc14Task` 每 4 ms 求解一次，模型节点间隔为 2 ms。更改周期时同步任务、预测模型与每节点力变化率。

`BALANCE_USE_SLIP` 同时选择控制反馈与位置积分的速度来源，1 使用融合速度，0 使用轮腿运动学速度。累计里程在本拍速度融合后积分，运行 FSM 捕获驻车原点。TinyMPC14 的驻车位置偏差来自 `FSM_RUNNING_POS_WEIGHT` 与腿角保护恢复斜坡的乘积。

`LEGLEN_TURN_ENABLE` 允许转弯协调调整 TinyMPC14 高度与横滚参考，驾驶侧倾限幅由 `BALANCE_USE_TURN_LIMIT` 配置。

## 物理参数入口

以下 MATLAB 路径均相对仓库根目录 `Matlab/`，固件路径相对 `Wheel_Leg_Code/`。

| 参数 | 权威入口与单位 | 同步核对与生成物 |
|---|---|---|
| 质量与支撑口径 | 训练 URDF，kg；实物参数记录在 `Tool/leg_config.m` | 当前固件由生成包提供质量。轮以上支撑质量扣除两轮，机身质量再扣除两腿 |
| 轮径、轮距、轮惯量、质心与机身惯量 | `mixmpc_pre/functions/tinympc14_urdf_config.m`，m、kg·m² | 训练模型参数随四文件发布包生成，轮距和轮径由估计器与控制器共用 |
| 腿标定表与补偿 | `Tool/leg_config.m` 的 19×4 表、弹簧与旋转补偿参数；m、rad、kg·m²、N、N·m | 生成 `Leg_Comp`、`Leg_SpringF`、`Leg_RollComp`、`Leg_CoriolisComp`。标定表腿长步长保持均匀，插值定位依赖此条件 |
| 气弹簧装车挂点 | `Tool/leg_config.m` 的 `Spr_s1` 小腿下销、`Spr_s2` 大腿上销，单位 m | `Leg_SpringF` 由腿长计算销距和固定摆角的沿腿力，两腿共用。控制器通过轴向请求 `F` 抵消弹簧力 |
| 五连杆运动学与力矩映射 | `Tool/model/Leg_Pos.m`、`Leg_Spd.m`、`Leg_Trq.m`、`Leg_InvTrq.m` | 这些符号表达式已固化连杆几何。换连杆尺寸或机构后必须重新推导并同步四个表达式；只修改 `leg_config.m` 或弹簧臂长不会更新这些表达式。Tool 构建后部署到 `Code/Math` |
| 平衡、高度与横滚预测 | `mixmpc_pre/config/tinympc14_config.m` | 配置状态与输入代价、轴力范围、力变化率和采样周期 |
| 减速比、轮力矩换算、腿长范围、俯仰参考 | `Code/Config/code_config.h`；无量纲、编码计数/N·m、m、rad | 减速比变化需重新核算 `M3508_TO_TORQUE`，不会自动联动；腿长范围需与 Tool 补偿域、模型网格、状态目标及转弯降高下限核对 |
| 安装极性与零点 | `Code/Config/polarity_config.h`；±1、rad | 同时核对 IMU 欧拉角、加速度、四元数坐标映射与四关节零点；轮电机反馈和发送方向需核对对应驱动实现 |
| 执行器能力与观测质量 | `Code/Control/distributor.h`；N、N·m、s、rad、m | 分配能力界与编码使用同一标定界；当前默认关节界引用协议量程，并非已标定能力。支持力箱与腿长模型核对，`EXECUTION_*_BOUND` 按新车模型重新推导，可用 `tests/derive_execution_quality.py` |
| 离地与运动调参 | `Code/Eatimator/air.h`、`Code/Control/turn_limit.h`、`Code/Control/vel_limit.h` | 由支持力实测校核离地阈值，按工作域校核速度、侧倾及降高 |

Tool 表当前存在既有惯量口径疑点：注释声明 `I_leg` 绕 pitch 轴，而按 `m_leg=1.855 kg` 与质心距离检查，19 行均不满足该口径下的 `I_leg ≥ m_leg·l_d²`。新车需确认惯量测量轴、质量范围和质心距离；本次不修改旧表，也不根据猜测修正模型。

## 完整重建与固件验证

在 MATLAB 中逐个进入模块目录运行以下命令，模块与 `Tool` 保持同级；不要使用 `addpath(genpath(...))`。迁移到新的工程目录时，先检查 Tool 的 `shared/leg_paths.m` 及各控制模块 config 的 `D.OUT_DIR`，确保输出进入目标新车工程。

| 顺序 | 模块目录 | 构建与验证 | 部署目标 |
|---|---|---|---|
| Tool | `Matlab/Tool` | `build_leg_tool`，`verify_leg_tool` | `Code/Math/Leg_*.c/.h` |
| TinyMPC14 | `Matlab/mixmpc_pre` | `build_mixmpc_online`，构建中执行 MATLAB 验证与 C 对拍 | `Code/Model/tinympc14.c/.h` 和 `tinympc14_data.c/.h` |

改动物理量、几何、采样周期、权重或模型后，重新生成对应模型并完成对拍。TinyMPC14 发布脚本核对四个文件的哈希后复制到固件目录。

部署后重新编译 EIDE。`tests/build_project.py` 可用 `--allocator clip/project`、`--diagnostics` 和 `--step-check` 验证不同配置。各构建的 `build_manifest.json` 保存实际生效值。上板验收覆盖方向、执行能力及求解耗时。

## 遥测与阶段观察

VOFA 任务每 10 ms 发送一次。当前使用 LPUART1、209700 baud 和 JustFloat 格式，通道顺序由 `Code/Task/vofa_task.c` 中实际传入的参数决定。下面的通道说明供对照相应的历史采集配置。

CH40/41/42、CH43/44/45 分别保存最近一次预测节点、终端回退控制拍的时标（ms）、两腿接纳总轴力之和与左减右差力（N）。每组按自己的时标去重，−1 表示本代尚无有效样本。CH46/47 是 CH02 同拍的左右腿矢状角，CH49 是俯仰角，单位均为 rad。CH48 是经配置极性换算的 IMU 加速度数组 Y 分量（g），含重力投影；与车辆横移或轮胎侧滑比较前需核实安装轴向。

CH50–53 使用 CH02 的控制时标。CH50 位 0、1 分别标记左、右腿反馈已通过本拍时序与有效性检查。CH51、52 给出对应侧的已建立轴力估计减接纳轴力（N），解读时使用该侧有效位。CH53 表示降高分配相对原逐腿裁剪结果削减了多少合力（N），未削减时为零。

采集降高过程时，在平地普通跟随模式下先保持静止，再轻推高度滚轮请求降高、保持、回中。保留整段原始 CSV。CH25 是滚轮，对应正向超过 20 个计数才请求降低。对照 CH26 行为层目标、CH27 MPC 参考、CH28 MPC 高度反馈及 CH11 原始高度。CH20 的位 22 表示陀螺行为持有高度目标，包含退出斜坡。CH30/31 是左右腿长，两者相减得到腿长差。

分析腿力时，配对使用 CH32/13（分配前请求的和/差）及 CH34/15（CAN 接纳码反算的和/差）。从和、差恢复左右腿的公式为 `左=(和+差)/2`、`右=(和-差)/2`。CH33 是分配后总力之和。关节电机力矩反馈反算轴力为 CH35/16，估计的被动弹簧轴力为 CH36/17，两者相加可与接纳指令比较。用 CH02 控制采样时标对齐。CH20 位 20/21 标记接地分配及同拍计划与执行已配对，CH39 累计关节请求越界的控制拍数。

解析已有 CSV 时，读取 CH20 的位 23（掩码 `0x800000`）。该位为 0 时使用下表左列的原含义，为 1 时使用右列的后台诊断含义。

| 通道 | 原高度与横滚诊断帧（位 23 为 0） | 后台诊断帧（位 23 为 1） |
|---|---|---|
| CH01 | IMU 接收时标，ms | 后台取得活动输入的累计尝试次数 |
| CH04 | 分配与 CAN 接纳记录的状态时标，ms | LPV 调度模型累计重算次数 |
| CH08 | 原始俯仰角速度，rad/s | 开始计算前样本已过预测时域的累计次数 |
| CH10 | 左右腿长差，m | 非有限输入或调度模型准备失败的累计次数 |
| CH12 | MPC 总轴力请求差，N | 求解器未返回收敛序列的累计次数，结合 CH24 查看是否达到迭代上限 |
| CH14 | 分配后的总轴力差，N | 求解已经收敛、同代次发布时样本过期的累计次数 |
| CH18 | 分配前净髋力矩差，N·m | 求解已经收敛、发布时因停止或代次改变被取消的累计次数 |
| CH19 | 电机反馈反算髋力矩差，N·m | 最近一次后台任务调用耗时，µs，含抢占以及无活动输入时的短调用 |
| CH24 | 原始偏航角速度，rad/s | 最近一次实际进入 ADMM 的迭代次数 |
| CH37 | 左腿矢状面角，rad | 最近一次活动求解从采样时标到返回时刻的年龄，ms |
| CH38 | 右腿矢状面角，rad | 成功提交可消费预测序列的累计次数 |

在同一接地段比较计数增量。CH01 的每次活动尝试结束后恰好计入 CH08、CH10、CH12、CH14、CH18 或 CH38 之一，截取时可有一次求解在途。CH03 是最近成功发布时标，CH22 累计前台使用终端反馈的毫秒控制拍，CH23 累计已发布序列的超龄作废。若 CH22 随 CH00 每毫秒增加且 CH38 持平，可从各拒绝计数定位整段回退原因。CH24 保持最近 ADMM 的迭代数，CH19、CH24 与 CH37 各自按对应调用更新。

若 CH14 持续增长，在同一采样窗口对比 CH04 和 CH01 的增量。两者同步增长表示频繁重算模型，CH04 持平时的活动尝试沿用当前模型。CH04 记录重算次数，CH19 记录整次后台任务耗时，具体模型重算与 ADMM 各自耗时需要分段计时。

判断高度与横滚是否争用腿力时，以降高前稳定段的 CH32 为基准，按完整横滚周期比较 CH32 的均值、CH13 的幅度和 CH53 的削减量。作为修复前的对照，固定高度反馈 0.27 m、参考 0.22 m，原控制器静止时请求合力为 93.6 N；输入 ±2°、10 Hz 的横滚后为 151.4 N，超过直立支撑力 144.5 N。实车数据同时核对 CH34、CH35+CH36 的跟随，以及同一时段 CH39 的增量和 CH50 的有效位。

启用某个专有诊断模块时，同时打开任务上方对应的模块诊断快照读取段，并按实际发送顺序核对通道表；原 64 路分配帧需要关闭其他发送项。`BALANCE_DISTRIBUTOR_COMPARE` 只额外计算另一分配策略，不选择遥测内容。

串口实例与波特率以 CubeMX 配置及驱动实际句柄为准；现有部分串口注释和历史采集说明存在不一致，迁移时按配置核对，不能只根据注释接线。蜂鸣器由 `APP_USE_MUSIC` 选择，TIM12 参数仍由 CubeMX 管理。
